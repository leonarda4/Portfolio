# Project case-study writing template

Case-study opening order is mandatory: title, summary, project metadata, then results or other content. Never place highlights, media, or a teaser above the metadata. Preserve existing project titles unless explicitly asked to rename them. Do not use em dashes in authored copy.

Duplicate this file for each project and replace the bracketed prompts. It follows the eight sidebar sections and the exact block order in `src/content/project-one.json`.

The word counts below are recommended writing budgets for this implementation, not measured counts from Jessica Hsu’s site. Aim for roughly **1,800–2,400 words overall**, including headings, captions, and labels. The goal is a long, visual case study made of short passages:not a continuous essay. Actual page length also depends on image proportions.

## Writing and length rules

| Element | Target | How to write it |
| --- | --- | --- |
| Project title | 8–14 words | Describe the improvement and audience; avoid a project name alone. |
| Section headline | 6–14 words | State the finding, decision, or benefit. It should make sense when skimmed. |
| Eyebrow | 1–4 words | Label the stage: Research, Insight, Iteration, Final design. |
| Standard paragraph | 35–60 words, 2–3 sentences | One idea: explain the situation, then its consequence or design implication. |
| Decision paragraph | 50–75 words, 3–4 sentences | Explain the alternatives, evidence, trade-off, and choice. |
| Column/card paragraph | 15–35 words, 1–2 sentences | Make one specific point. Keep neighboring columns similar in length. |
| Feature explanation | 30–45 words, 2 sentences | Say what users can do and why it solves their problem. |
| Image caption | 5–12 words | Identify what the image demonstrates. Avoid repeating the preceding paragraph. |
| Quote | 15–30 words | Use an actual quote, with a short attribution. |
| Metric label | 3–7 words | Name the outcome and direction of change. |
| Metric note | 5–12 words | Give the baseline, sample, timeframe, or measurement method. |

Keep most body fields to one paragraph. If a passage exceeds 80 words, tighten it or split the idea into another block. Sentence counts are a guide; prioritize clarity over hitting a number exactly. Use “I” for your contribution and “we” for shared work. Replace methods and examples with work you actually did.

## Project card and page header

These fields sit above the sidebar sections. The card title is also the case-study page title.

- **Project title : 8–14 words:** [Improving / simplifying / enabling WHAT for WHOM]
- **Card summary : 12–22 words, one sentence:** [The outcome, with evidence or a clear description of the improvement]
- **Three tags : 1–3 words each:** [Industry] / [Product category] / [Platform]
- **Cover image:** [A strong final-product composition; also used as the case-study hero]
- **Cover alt text : 8–20 words:** [Describe the meaningful content of the image]
- **Project type : 3–10 words:** [Client, context, or type of engagement]
- **Team : 8–20 words:** [Your role and the collaborators involved]
- **Tools : 2–6 tool names:** [Tools used]
- **Timeline : 4–10 words:** [Duration · Month–Month Year]

## 01 : Overview

Sidebar ID: `overview`. Give readers the product, your contribution, and an early glimpse of the result before explaining the process.

### 1. Two-column introduction

**Overview : 50–70 words, 3–4 sentences**

[What is the product? Who uses it? What were they struggling with? What did this project aim to improve?]

**What I did : 40–60 words, 2–3 sentences**

[Name your ownership, the main activities you led, and how you worked with others. Make your individual contribution unambiguous.]

### 2. My impact

**Headline : 8–14 words:** [The most important change your work created]

**Paragraph : 20–35 words, 1–2 sentences**

[Connect the outcome to the user or business goal. State whether it was observed in testing or after release.]

### 3. Two outcome metrics

**Metric 1:** [Value] / [3–7-word label] / [5–12-word evidence note]

**Metric 2:** [Value] / [3–7-word label] / [5–12-word evidence note]

If there are no reliable numbers, use truthful qualitative outcomes and short values such as “Validated” or “Shipped.” Do not invent percentages to fill the layout.

**Paragraph : 20–35 words, 1–2 sentences**

## Moving the draft into the website

Edit the relevant file in `src/content/`. The mapping is:

| Draft element | JSON field |
| --- | --- |
| Project card / header | Top-level `title`, `summary`, `tags`, `cover`, `coverAlt`, `metadata` |
| Sidebar section | Entry in `sections`; preserve its `id` |
| Eyebrow / headline / paragraph | `text` block: `eyebrow`, `title`, `body` |
| Parallel explanations | `columns` block: each item’s `title` and `body` |
| Outcome | `metrics` block: each item’s `value`, `label`, `note` |
| Image and caption | `media` block: `src`, `alt`, `label`, `layout` |
| Quote | `quote` block: `quote`, `attribution` |
| Supporting link | `resources` block: each item’s `title`, `description`, `url` |

The current renderer treats body fields as plain text: Markdown bullets, bold markers, and headings inside a string will not become formatted elements. Use the separate fields provided. A `pair` media slot takes one composed image containing both screens. Write alt text separately from the visible caption.

The full template contains **47 blocks and 14 media slots**, plus the project cover. Keep that sequence for a comparable long-form rhythm. Do not pad the writing to force a pixel height: use relevant visual evidence and preserve similar image proportions. Read through the title, headlines, and captions alone to check that the project’s story is clear before publishing.
